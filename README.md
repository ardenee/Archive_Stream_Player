# Archive Stream Player

**Play music directly from ZIP, 7z and RAR archives in your favourite Windows music player.**

Archive Stream Player lets supported players browse the audio tracks inside an archive and play them as individual songs. You don't have to manually unpack an entire album first. The source is published here and the project provides a shared archive engine with several player-specific integrations.

## What it can do

- **Open ZIP, 7z and RAR archives** containing music, including supported split/multipart and solid archives.
- **Display and queue individual songs** from archives in players that offer native archive or playlist integration.
- **Play common music formats**, including MP3, FLAC, WAV and Ogg Vorbis. AAC, M4A and WMA depend on the player's available decoders.
- **Read encrypted archives** using a shared password list and interactive prompts in supported native and bridge players. Passwords are only saved after explicit consent and successful verification.
- **Seek within supported tracks**, so playback does not have to start from the beginning.
- **Use stream-first playback:** decompress directly from an archive where possible; if streaming fails or is unavailable, use the configured RAM buffer, then a reusable managed disk cache only as a last resort. Cached tracks can be reused by different players without repeating extraction.
- **Configure shared playback preferences** across adapters: memory limits, managed-cache size and age, password lists/prompts, background solid-archive preparation, track-title presets and optional per-player diagnostic logs. Open or clear managed cache and generated logs from the common settings page. Winamp and foobar2000 also retain their native preferences.
- **Work without separate archive-extraction programs or runtime archive DLLs.** Archive reading is built into the project's components.
- **Keep archives intact.** Playing a track does not rewrite or modify the original ZIP, 7z or RAR file.

Not every feature above has been verified in every player or with every archive. Availability depends on the player adapter, archive format, codec and encryption method.

**MediaMonkey native-first migration (15 November 2026):** Local `.ast` files solve the earlier real-host Winamp virtual-path dispatch failure: MediaMonkey now loads our matching x86 input DLL and calls its own archive decoder, including real native MP3/OGG playback and seek/resume inside ZIP/7z/RAR. The statically linked x64 list-only helper creates a local playlist and tiny per-entry references and terminates before opening any HTTP socket. The packaged Tools addon passed native ZIP MP3/OGG GUI seeking; all seven ZIP codecs started natively, though WAV/AAC had intermittent resume-display failures in the full seven-track sequence and both passed again individually and together. The addon compares the installed input DLL hash with its companion before enabling native mode, otherwise automatically retaining the older HTTP bridge. Install **both** [MediaMonkey companion MMIPs](mediamonkey_archive_stream/README.md). Native encrypted/multipart host acceptance, live repaint of existing rows, speaker output and PCM-content parity are not yet certified.

**MusicBee input compatibility investigation (15 November 2026):** A standalone x86 BASS/Winamp compatibility test loaded our existing Archive Stream Winamp input DLL through MusicBee's included `bass_winamp.dll`, opened an indexed MP3 from ZIP and returned **65,536 decoded PCM bytes**. The repeatable [native BASS test](musicbee_archive_stream/test_native_bass_winamp.ps1) does **not** establish MusicBee host dispatch. A disposable MusicBee 3.7 host imported the input DLL via **Player → Input Plugins → Import Winamp**, restarted successfully and accepted queued virtual/physical descriptor/ZIP paths, but playback remained stopped and no input decoder callback ran. Trial playback hooks were reverted; HTTP/local-file paths remain active. The existing seven-codec real-host playback and seek regression passed again after a null-safe diagnostic fix.

**XMPlay native ZIP improvement (15 November 2026):** XMPlay 4.1's actual Options → Decoders list places its built-in `ZIP archives` decoder before Archive Stream XMPARC. Real Store/Deflate ZIP MP3 GUI seek/resume passed (9→16→434→441 and 8→16→434→441 played pixels) with no XMPARC `LIST_OK`/`STREAM_OK` because the built-in decoder intercepted ZIP. The launcher now checks ZIP local headers without inflating audio and chooses native playback only for recognized, unencrypted, local-size Store/Deflate ZIP; encrypted flags, ZIP64, data descriptors, other methods, malformed headers and split files retain HTTP. The actual launcher started disposable XMPlay **without our native DLL**, passed GUI seek/resume (5→13→434→441) and started no HTTP server. See [ZIP eligibility and real launcher QA](archive_player_bridge/test_xmplay_builtin_zip.py) and [real ZIP GUI QA](xmp_archive_stream/test_real_builtin_zip_gui.py). Built-in ZIP is not the shared Archive Stream decoder: password, title, cache and host-on-demand settings are not certified; request `-UseHttpBridge` for those features or large entries.

**Native migration (14 November 2026):** The shared `archive_player_bridge/launch-archive.ps1` launcher now opens verified single-file 7z and RAR archives via the installed native `xmp-archive-stream.dll` **without HTTP**. XMPlay 4.1 internally handles ordinary ZIP before XMPARC: restricted unencrypted Store/Deflate ZIP now opens natively, while unsupported/encrypted ZIP and split-volume paths retain HTTP. Isolated real XMPlay x86 played a non-solid 7z MP3 with `LIST_OK` / `STREAM_OK`, advancing progress and no disk cache. Missing native plugins fail explicitly on native-eligible 7z/RAR; use `-UseHttpBridge` for on-demand host reads of large entries. XMPlay XMPARC still requires a host-owned decoded buffer. Earlier MediaMonkey virtual/descriptor input forms did not dispatch; the later native `.ast` manifest format now reaches the actual Winamp input decoder, as verified above. Existing HTTP compatibility remains supported.

**VLC native SDK migration (15 November 2026):** The v1.3 statically linked VLC 3 x64 access module enumerates archives entirely inside VLC at `ast://<hex-encoded-path>/list/album.m3u8`. This removes HTTP, the separate builder process, temporary playlists and duplicate first-use encrypted-filename prompts for the tested hosts. Real VLC 3.0.24 verified exact WAV PCM parity from ZIP/7z/RAR5, long-distance native seeking and solid-7z RAM fallback. The **actual PowerShell launcher** played two header-encrypted 7z tracks with one password dialog and two direct streams, and two header-encrypted RAR5 tracks with one prompt and two RAM routes; zero managed disk cache and unchanged password lists. Windows FileVersion 1.1+ identifies in-process playlists, v1.2+ enables native `-PasswordList`, and v1.3+ enables native `-MemoryMB`, `-CacheLimitMB` and `-TitleTemplate`. Older unversioned modules retain the external builder; pre-v1.2 modules use HTTP for `-PasswordList`. The DLL can load externally through `VLC_PLUGIN_PATH` without installation changes. `-UseHttpBridge` and missing/incompatible DLLs retain HTTP; **memory/cache/title overrides now stay native on v1.3**, while older DLLs retain the bridge for those options. See [`vlc_archive_stream/README.md`](vlc_archive_stream/README.md). **Save=Yes** is now real-libVLC verified for individual encrypted 7z/RAR5 tracks with visible and encrypted filenames: accepted passwords were saved once after successful PCM decode, while incorrect/cancelled entries wrote nothing. The native v1.2 two-track launcher is **also certified for Save=Yes**, with a per-child-process password-list path, zero HTTP/cache, and wrong-password/cancel fail-closed tests. The real v1.3 launcher also passed ZIP two-track custom-title generation and solid-7z memory/cache limits: 1 MiB RAM with no disk fails closed; 5 MiB disk allowance enables byte-identical cache only after RAM is insufficient. Per-codec seeks are SDK API tests (OGG via position API, others via time API); most short fixtures use VLC buffering rather than invoking the archive-reader seek callback. **Actual VLC GUI seek clicks now pass 21/21** across all seven codecs in ZIP, non-solid 7z and RAR5, with real elapsed-time jump/continued playback and direct archive streaming (no HTTP/cache). Real VLC also shows both newly generated custom playlist titles for ZIP/7z/RAR5 in the actual GUI; speaker output, live repaint of already-queued titles and untested encryption layouts remain open.

**Native plugins** can give their player a more integrated experience. **Bridge-based integrations** open a temporary local playlist and need the Archive Stream bridge to remain running during playback. They are not full native archive browser plugins.

## Working functions

The following have passed tests in at least one supported player or in the shared archive backend:

- [x] List audio tracks inside ZIP, 7z and RAR archives.
- [x] Read ordinary and supported solid/nonsolid archives.
- [x] Read supported split and multipart archives.
- [x] Decrypt supported password-protected ZIP, RAR and 7z entries. Encrypted 7z headers and AES+Copy/LZMA2 streams (including Copy+Delta, split archives and solid fallback) pass x86/x64 parity and wrong-password regressions.
- [x] Stream eligible archive entries without extracting an entire album. ZIP, non-solid 7z and non-solid RAR direct HTTP streams pass x86/x64 range tests (`archive_player_bridge/test_stream_priority.py`).
- [x] Use memory before temporary files when archive entries cannot stream, including native in-RAM decryption of encrypted RAR5 entries. The encrypted RAR5 variants pass x86/x64 memory and bridge parity regressions. Injected mid-stream failure recovery passes 8/8 native AIMP, 8/8 native foobar2000 and 4/4 HTTP bridge scenarios, including memory and cache routes with exact source-byte parity.
- [x] Verify decoded audio bytes and seeking. Real Winamp/WACUP x86 tests deliver PCM to a silent QA sink for seven audio codecs and verify 18-second host IPC seek/flush/resume without speaker hardware. A synthetic encrypted 7z WAV now also passes exact 16-bit sample-value verification across more than 365,000 PCM samples per host, including post-seek playback; other codecs remain delivery-only.
- [x] Use a shared managed cache and common settings policy in Winamp, foobar2000, AIMP, XMPlay and the HTTP bridge. A synthetic solid 7z test verified background preparation, persistent reuse across Win32/x64 bridge processes, and cache invalidation after a source archive changes.
- [x] Share opt-in debugging and per-host diagnostic log files (including Unicode paths); Win32/x64 HTTP bridge, AIMP Win32/x64, XMPlay Win32, and MusicBee x86 adapter logging plus selective cleanup pass regression tests. Win32/x64 cache-age startup maintenance and preservation of unrelated cache-folder files are also verified. Shared title presets work in Winamp's input/expander metadata (with a title-cache flush), AIMP virtual-file metadata, M3U/ASX bridge playlists, foobar2000's live-refreshing `%archive_stream_title%` field, and XMPlay's reversible archive display aliases. Two-architecture real foobar2000 live field-refresh tests and two-track ZIP/7z XMPlay extraction/alias regressions pass.
- [x] Expand archives into individual playlist tracks in supported hosts.
- [x] Provide portable, self-contained archive readers without external extraction utilities.
- [x] Build the shared backend and newer playback bridge for both 32-bit and 64-bit Windows.
