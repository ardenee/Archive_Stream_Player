# Archive Stream Player — feature matrix

**Snapshot:** 14 November 2026, updated after repeatable *genuinely portable-profile* MediaMonkey 2024 seven-codec ZIP queue, seven shared titles, advancing playback and archive-direct streaming plus **all seven MP3/OGG/FLAC/WAV/WMA/M4A/AAC real-host GUI seek/resume passes** using the production Ogg/Vorbis duration metadata fix. Also includes isolated real MediaMonkey 2024 synthetic AES 7z and RAR5 password entry, playback and GUI seeking, cancellation for both, and RAR5 wrong-password rejection; encrypted RAR5 routes to bounded RAM when streaming is unsupported. First-use RAR5 encrypted filenames with an empty saved list now also pass real MediaMonkey 2024 header prompt, playback/GUI seek and cancel/wrong-password rejection; Win32/x64 bridge UI and byte parity pass separately. Includes real MusicBee 3.7 SDK playback-position and GUI seek tests for all seven codecs (MP3/OGG/FLAC/WAV/WMA/M4A/AAC), with five byte-verified local fallbacks and MP3/AAC retaining HTTP direct streaming. This verifies the host's Playing state, advancing position and successful seek/resume, **not** audible output or PCM-content parity. Also includes real Winamp 5.9/WACUP x86 PCM/password regressions, an isolated XMPlay 4.1 bridge MP3 GUI seek/resume observation with direct stream routing, and real MediaMonkey 2024 affirmative encrypted RAR5 filename password-save consent (only after verified data decode). Base matrix published at `96c55b7`. This is a **verification matrix**, not a claim that every function has passed real-player acceptance tests. The [main README](README.md) describes the project; [PLAYER-ADAPTERS.md](PLAYER-ADAPTERS.md) contains implementation detail and test evidence.

## Status legend

| Mark | Meaning |
| --- | --- |
| **H** | Observed in an actual host-player process or its UI. Includes verified archive reads, elapsed playback progression, or decoded output where specified; **does not automatically mean audible speaker output**. |
| **T** | Passed an automated adapter contract, real-player SDK/harness, shared-backend or HTTP-bridge regression. **Not** necessarily tested via the target player's UI. |
| **I** | Implemented/connected, but the specific end-to-end behavior is not yet certified. |
| **L** | Available with an important host limitation or manual refresh/reimport requirement. |
| **?** | Not verified; do not present as working. |
| **—** | Not offered in this integration mode. |

A player can have **H** for obtaining archive audio and **?** for audible output or interactive seeking. Status applies to the *specific column*, not to all codecs or all archive layouts.

## Winamp-compatible host codec acceptance (silent PCM)

The following **H** results came from actual isolated Winamp 5.9 x86 and WACUP x86 processes, not merely a backend decoder harness. The host loaded the Archive Stream input plugin, handed decoded PCM to a **test-only, realtime simulated output plugin**, and its IPC seek to 18 seconds triggered an output flush followed by more PCM writes. The output plugin never opens speakers. This is **not** audible-output certification. Additional WAV-specific verification now checks the actual 16-bit PCM values of a synthetic AES+LZMA2 7z file: Winamp and WACUP x86 each produced zero mismatches across over 210,000 samples before an 18-second seek and over 365,000 cumulative samples after seeking and stopping. This is exact sampled PCM-content parity for that controlled WAV only; MP3/OGG/FLAC/WMA/M4A/AAC currently certify PCM delivery, not content parity.

**Seek reliability fix:** Pending seek requests now preempt the audio output-write loops for MP3/WAV/FLAC/OGG/Media Foundation in `in_archive_stream/playback.cpp`. The DEV acceptance uses an isolated, device-independent sink to test decoding and seek behavior; it does not assert that real speaker hardware is configured.

Supported solid layouts use RAM or cache instead of claiming independently seekable archive streams. Encrypted Copy/Store 7z requires a per-entry CRC verification pass before streaming, and exotic coder chains are not universally certified.

**Ogg/Vorbis edge-case transport (T, Win32/x64):** `archive_player_bridge/test_ogg_edge_cases.py` verifies an ordinary logical stream (199 seconds), a genuine two-stream chain with rewritten serials and valid Ogg page CRCs, and a stream missing its last EOS page. All three preserve exact HTTP ranges, with `stream=9 memory=0 cache=0` per architecture. Chained/truncated streams intentionally advertise unknown duration (`#EXTINF:-1`) rather than a misleading partial duration. This **does not** certify chained-stream host decoding, seek position, or audible output.

## Known host limitations

- **WACUP x64:** Its tested preview does not load third-party Winamp plugin DLLs. Use the bridge; this is not a permanent claim about future WACUP versions.
- **XMPlay native:** `launch-archive.ps1 -Player XMPlay` now passes tested single-file 7z and RAR archives to installed XMPARC without HTTP. Real non-solid 7z and RAR5 MP3 host playback with `LIST_OK` / `STREAM_OK` is verified. The real XMPlay host did not dispatch tested ZIP files to XMPARC, so ZIP and split-volume files retain the HTTP bridge automatically. `XMPARC` still hands a decoded memory block to XMPlay; host-on-demand streaming requires explicit `-UseHttpBridge`. Indexed display aliases retain decoding compatibility, but existing playlist row labels cannot be repainted by the archive plugin's API.
- **foobar2000:** The live title field is `%archive_stream_title%`. An existing playlist column must use that field (for example `$if2(%archive_stream_title%,%title%)`); the plugin intentionally does not rewrite `%title%` or file tags.
- **MusicBee:** Real MusicBee 3.7 queues and plays all seven tested ZIP codec entries with host-reported `Playing` and advancing playback position. Each passed a GUI seek followed by continuing playback-position progression. MP3 and AAC remain archive-backed direct HTTP streams; the bridge observed genuine nonzero HTTP Range requests on their seeks. Raw OGG/WAV/WMA/M4A HTTP failed in host tests; FLAC played over HTTP but repeatedly restarted at byte zero after seeking and failed to resume. Thus OGG/FLAC/WAV/WMA/M4A use **session-local audio files**, all with SHA-256 parity and normal-shutdown cleanup; the shared `CacheLimitMB` bounds their combined temporary disk use and zero blocks this fallback. The MusicBee queue API accepts paths/URLs but not in-memory audio sources, so this host-specific route cannot use the shared RAM-preferred fallback before disk. These player-state/seek checks **do not establish audible speaker output or PCM-content parity**. Shared title-template display and in-host password dialogs remain uncertified; abnormal termination can leave decrypted audio on disk.
- **MediaMonkey:** MediaMonkey 5 does not support Winamp general-purpose plugins. Its separate JavaScript Tools add-on runs the static shared bridge, waits for a private ready manifest and inserts authenticated HTTP tracks with `app.player.addTracksAsync()`; the bridge stays alive only after a queue acknowledgement. The real Tools menu/native Windows archive picker passed direct host acceptance. A second, repeatable test now starts the actual MediaMonkey 2024 player with `[Portable] IsPortable=1` and a separate MM5.DB, safely cancels its first-run scan wizard, and accepts a seven-codec stored ZIP through the *same native addon action*, with only the file-picker step test-injected. All seven tracks show new shared titles, progress in the player UI and cause direct `ROUTE_STREAM` requests without cache. GUI seek/resume passed for **all seven codecs in one post-fix run**: MP3 ~05→220→224s; OGG ~04→126→129s; FLAC ~05→303→307s; WAV ~05→176→180s; WMA/M4A ~05→455→458s; AAC ~04→159→162s. OGG initially lacked an HTTP duration and ended on seek, but providing accurate Vorbis duration from bounded archive prefix/tail probes restored seek/resume without extraction. The test validates the original user's MM5.DB/settings hashes remain unchanged and cleans up its disposable profile. Separate synthetic encrypted 7z and RAR5 host tests now verify password entry, playback/GUI seeking and cancellation; RAR5 additionally rejects incorrect passwords. The shared backend uses direct streaming for this 7z layout and in-memory UnRAR when RAR5 encrypted direct streaming is unsupported; the default zero-disk test cache remained unused. **First-use RAR5 encrypted filenames with no saved password are also now verified in a real portable MediaMonkey process:** successful header prompt, native queue, AAC playback, GUI seek/resume, zero disk cache and zero password-list writes; separate cancel/wrong-password startup tests prevented queue publication. **Encrypted multipart RAR5 is now additionally verified in a real portable MediaMonkey host:** a four-volume, encrypted-filename AAC entry played, sought and resumed using RAM, with zero disk-cache extraction and unchanged password list. **Two-entry solid RAR5 now also passed real MediaMonkey 2024 GUI seek/resume**, after earlier intermittent portable-host startup failures: MP3 00:15→02:45→02:52 and AAC 00:15→03:46→03:53. The bridge logged three RAM fallback operations, zero disk-cache writes, and the original profile hashes remained intact. **A real RAR5 encrypted-header Save=Yes dialog has now passed verified-only password persistence**, unlike other archive layouts for which storage consent has not been individually accepted. Separate real portable-host ZIP MP3 title-refresh QA changed the active authenticated bridge playlist, observed the existing row repaint automatically to AST_QA_TITLE_REFRESHED, and confirmed playback progress, direct streaming, zero memory/cache routes and unchanged original profile hashes. Multi-entry live title refresh is explicitly disabled: a two-track update caused intermittent loss of player-source requests, while a later collection-only variant played OGG but not the first selected MP3. A protective guard leaves multi-entry Now Playing rows unchanged; both original MP3/OGG tracks subsequently played through direct streams without cache, and the single-entry MP3 refresh still passed real-host playback. No loudspeaker or PCM parity is inferred.
- **VLC / WMP:** Both use playlists/HTTP rather than native archive decoder plugins. VLC passed a dummy audio-output test; WMP full playback has not passed.
- **All players:** Audible-speaker output, all codecs, every encryption layout, GUI seek behavior, bridge-client/player-level prompt handling and automatic title repaint still need per-host verification where marked **?** or **I**. Native foobar2000 password cancellation is now verified; do not extrapolate it to other hosts.
